# 测试用 TLS 证书（仅用于单元测试，请勿用于任何真实用途）

本目录下的 `cert.pem` / `key.pem` 是一份**自签名的 localhost 证书**，
**唯一用途**是让单元测试能起一个真实的 HTTPS 服务器。

## 为什么需要它

问题 39 把远程名单下载收紧为**仅 https**（明文 http 直接拒绝）。
原先 `domain_set` / `ip_set` 的测试用明文 http 回环服务器验证"下载 / 缓存 / 定时刷新"，
收紧后必须改用真实 HTTPS，否则测的就不是 `https_only` 真正生效的那条路径。

## 安全性说明

- 这是**测试专用**的自签证书，只对 `localhost` / `127.0.0.1` / `::1` 有效，
  与任何生产环境的证书或密钥无关，**不是泄漏的密钥**；
- 生产代码**不使用**这份证书：信任它的开关是 `http_client` 里 `#[cfg(test)]` 的
  **线程局部**变量，正式编译下那段代码根本不存在；
- 证书有效期设得很长（36500 天），是为了避免测试因证书过期而突然失败。

## 如何重新生成

配置见同目录的 `openssl.cnf`（SAN 含 `localhost`、`127.0.0.1`、`::1`）：

```bash
openssl req -x509 -newkey rsa:2048 -sha256 -days 36500 -nodes \
  -keyout key.pem -out cert.pem -config openssl.cnf
```

> 注意：本机（Windows）可能没有 `openssl`；离线环境下也没有 `rcgen` 之类的
> 证书生成库可用，所以这份证书是**预先生成并随仓库提交**的。
> 重新生成后**无需改动任何代码** —— 测试通过 `include_bytes!` 读取这两个文件。
